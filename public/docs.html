lockAdmin access

The admin dashboard is protected by a login. The listener page has no login — phones on the network just open the shared /streams link.

  • Sign in at http://localhost:3001/dashboard (or in the Electron app window) with your admin username and password — the defaults ship in the project README.md under “Admin access”, and can be changed with the ADMIN_USERNAME / ADMIN_PASSWORD environment variables.
  • Admin is also locked to localhost: other machines on the network only ever see the listener page, even with valid credentials.
  • Never port-forward ports 3001/8200 to the internet — the localhost lock only protects you on your LAN.
  • Remote admin over the internet: use a VPN like Tailscale instead of exposing ports.

podcastsStreams

“Audio source busy — already used by …”

One audio input can feed one running stream at a time. Windows audio capture is exclusive per process, so a second stream on the same source cannot start.

  1. Stop the other stream named in the message, or
  2. Edit this stream and pick a different audio source, then Start.

“Audio source … could not be opened”

FFmpeg could see the device name but not open it as a capture device.

  1. If the source is a virtual camera's audio pin (e.g. OBS Virtual Camera), it cannot be captured — use OBS's actual audio output via a virtual cable (VoiceMeeter / VB-Cable) instead.
  2. Close other apps holding the mic (Zoom, Teams, Discord, Audacity, OBS itself).
  3. Restart VoiceMeeter / VB-Cable if you use virtual devices, then Refresh Devices.

“Cannot connect to Icecast”

  1. Check the Icecast panel on the dashboard — it should say Online. Start it if not (LANStreamer also auto-starts it when you go live).
  2. Port conflict: run netstat -ano | findstr ":8200" — if another app (e.g. Docker) holds the port, stop it or change the port in icecast.xml.
  3. Restart Icecast from its panel (Stop → Start).
  4. Windows Firewall: allow icecast.exe on private networks.

Stream stuck on “starting” / listener can't hear anything

The stream row status refreshes every 5 seconds. If a stream shows an error or stopped:

  1. Open the error's Details on the row — the top line says what failed.
  2. If the machine's IP changed (DHCP), restart LANStreamer; it re-syncs Icecast's hostname automatically.
  3. Ask listeners to tap play again — the listener page auto-resumes a stream that comes back on air.

micAudio sources

Devices listed twice

Fixed in current versions — duplicate entries are de-duplicated. If you still see doubles after plugging a new device in, click Refresh Devices (icon in the sources card).

Routing app audio into LANStreamer

Windows only exposes microphones as capture devices. To stream what a player/DJ app plays, install a virtual cable and pick it as the stream source:

  • VoiceMeeter (donationware) — mixer + virtual outputs.
  • VB-Audio Virtual Cable — simple in/out pair.
info Pick the cable output (what apps play into) as LANStreamer's input source, and set the same cable as the default playback device in your music app.

wifiNetwork & phones

Listener address

Listeners open http://<your-ip>:3001/streams — use the QR code / copy button in the dashboard header to share the exact address.

The IP changed (DHCP)

LANStreamer detects IP changes and re-syncs, but bookmarks on phones still point at the old IP. Best fix: give the streaming PC a static DHCP reservation in your router, then have listeners re-open the shared link once. Listeners can also bookmark /streams in their browser.

Page is blank

A blank page means the server isn't reachable (wrong IP, server off, or different Wi-Fi). The listener page itself shows “No live streams” whenever the server is up but nothing is on air.

speedLatency

Total delay from mic to ears is typically 2–6 seconds. Fastest wins:

  • Operator side: 5 GHz Wi-Fi or wired for the streaming PC; keep it away from congestion; QoS/streaming priority on the router helps on busy networks.
  • Listener side: phones on the same AP/SSID; close background streaming apps; wired headsets avoid Bluetooth's extra 100–200 ms.
  • In LANStreamer: lower bitrate (128 kbps) trims buffer a little; keep the listener volume above ~50% and use the on-page volume.

Full write-up: docs/LATENCY.md in the repository.

memoryMinimum specs

  • Windows 10/11 (64-bit), 4 GB RAM, dual-core CPU
  • FFmpeg and Icecast 2.4+ (bundled with the installer)
  • Wired or solid Wi-Fi to the same network as the listeners
  • Listeners: any modern phone browser (Chrome/Safari/Edge, ~2019+)
