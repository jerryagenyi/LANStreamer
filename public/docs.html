lockAdmin access

The admin dashboard is protected by a login. The listener page has no login — phones on the network just open the shared /streams link.

  • Sign in at http://localhost:3001/dashboard (or in the Electron app window) with your admin username and password — the defaults ship in the project README.md under “Admin access”, and can be changed with the ADMIN_USERNAME / ADMIN_PASSWORD environment variables. On first run the dashboard shows a banner stating the defaults and how to change them; it disappears once you set your own.
  • Change it in the app: dashboard → sidebar → Admin account card — new username + password, applies immediately (works in the desktop app, where there is no .env).
  • Forgot your password? On this PC, delete the admin login file and restart LANStreamer — the documented default login returns, and you can set a new one from the Admin account card. Installed app: %APPDATA%\LANStreamer\security.json · from source: config\security.json. (The login page shows this hint too.)
  • Admin is also locked to localhost: other machines on the network only ever see the listener page, even with valid credentials.
  • The bundled Icecast is hardened for you: it only listens on this PC (127.0.0.1) and its passwords are randomly generated per install — listeners get audio through LANStreamer's port 3001, never Icecast directly. Using your own Icecast install? Change its stock passwords; the dashboard warns until you do.
  • Never port-forward ports 3001/8200 to the internet — the localhost lock only protects you on your LAN.
  • Remote admin over the internet: use a VPN like Tailscale instead of exposing ports.

podcastsStreams

Start with the app (auto-start)

Streams saved with Start with app enabled come up automatically when LANStreamer launches — including the Icecast server, which starts itself if it isn't running yet. Stop a stream and disable the toggle if you want it to stay down across restarts.

“Audio source busy — already used by …”

One audio input can feed one running stream at a time. Windows audio capture is exclusive per process, so a second stream on the same source cannot start.

  1. Stop the other stream named in the message, or
  2. Edit this stream and pick a different audio source, then Start.

“Audio source … could not be opened”

FFmpeg could see the device name but not open it as a capture device.

  1. If the source is a virtual camera's audio pin (e.g. OBS Virtual Camera), it cannot be captured — use OBS's actual audio output via a virtual cable (VoiceMeeter / VB-Cable) instead.
  2. Close other apps holding the mic (Zoom, Teams, Discord, Audacity, OBS itself).
  3. Restart VoiceMeeter / VB-Cable if you use virtual devices, then Refresh Devices.

“Cannot connect to Icecast”

  1. Check the Icecast panel on the dashboard — it should say Online. Start it if not (LANStreamer also auto-starts it when you go live).
  2. Port conflict: run netstat -ano | findstr ":8200" — if another app (e.g. Docker) holds the port, stop it or change the port in icecast.xml.
  3. Restart Icecast from its panel (Stop → Start).
  4. Windows Firewall: allow icecast.exe on private networks.

The app opened on port 3002, or “port 3001 already in use”

Another LANStreamer server instance is still running — usually a leftover node server from a terminal (the window with the “DO NOT CLOSE THIS TERMINAL” message), or a second copy of the app. Two instances share the same stream settings and fight over audio devices, so stop one:

  1. On the dashboard of the instance you're keeping, stop every stream and the Icecast server — that frees the audio devices cleanly (the stop buttons end the encoders properly).
  2. Note: there is deliberately no “stop server” button — a web server cannot stop itself over HTTP. To end the server process itself, close its terminal window (or quit the Electron app from the tray), or kill it from Task Manager (node.exe listening on port 3001).
  3. Relaunch the app — it takes port 3001 back and starts clean.

Stream stuck on “starting” / listener can't hear anything

The stream row status refreshes every 5 seconds. If a stream shows an error or stopped:

  1. Open the error's Details on the row — the top line says what failed.
  2. If the machine's IP changed (DHCP), restart LANStreamer; it re-syncs Icecast's hostname automatically.
  3. Ask listeners to tap play again — the listener page auto-resumes a stream that comes back on air.

micAudio sources

Devices listed twice

Fixed in current versions — duplicate entries are de-duplicated. If you still see doubles after plugging a new device in, click Refresh Devices (icon in the sources card).

Routing app audio into LANStreamer

Windows only exposes microphones as capture devices. To stream what a player/DJ app plays, install a virtual cable and pick it as the stream source:

  • VoiceMeeter (donationware) — mixer + virtual outputs.
  • VB-Audio Virtual Cable — simple in/out pair.
info Pick the cable output (what apps play into) as LANStreamer's input source, and set the same cable as the default playback device in your music app.

wifiNetwork & phones

Listener address

Listeners open http://<your-ip>:3001/streams — use the QR code / copy button in the dashboard header to share the exact address.

The IP changed (DHCP)

LANStreamer detects IP changes and re-syncs, but bookmarks on phones still point at the old IP. Best fix: give the streaming PC a static DHCP reservation in your router, then have listeners re-open the shared link once. Listeners can also bookmark /streams in their browser.

Page is blank

A blank page means the server isn't reachable (wrong IP, server off, or different Wi-Fi). The listener page itself shows “No live streams” whenever the server is up but nothing is on air.

speedLatency

Total delay from mic to ears is typically 1–2 seconds on a healthy LAN (a bit more on first join). Fastest wins:

  • Operator side: 5 GHz Wi-Fi or wired for the streaming PC; keep it away from congestion; QoS/streaming priority on the router helps on busy networks.
  • Listener side: phones on the same AP/SSID; close background streaming apps; wired headsets avoid Bluetooth's extra 100–200 ms.
  • In LANStreamer: lower bitrate (128 kbps) trims buffer a little; keep the listener volume above ~50% and use the on-page volume.
  • Virtual audio cables (VB-CABLE etc.): the cable itself is fast, but whatever plays INTO it may buffer seconds on its own — a Zoom call, a browser tab, a media player. Feed the cable from the most direct output available and set that app's buffer/buffering to its minimum. Also avoid Windows' "Listen to this device" routing (Sound settings → device properties) — it adds seconds of its own.
  • iPhone/Safari listeners: these use a compatibility playback path where the browser keeps its own (multi-second) buffer — latency there is higher by design. Android/Chrome/Edge/Firefox phones sit closest to live.

Cabled listeners are fine, Wi-Fi listeners are 5–6 seconds behind

On version 2.0.0 a single Wi-Fi drop moved that listener to the slower playback path for good. From 2.1.0 the page reconnects by itself and comes back to about 1 second. On 2.0.0: reload the listener page on the slow phone or laptop, or tap the channel off and on.

Full write-up: docs/LATENCY.md in the repository.

timerTesting the delay before an event

Expect about 1 second on a cabled laptop, 1–1.5 seconds on Android or a laptop over Wi-Fi, and a few seconds more on iPhones.

The 1-second test

  1. On this PC, play continuous music or speech in VLC into the cable you stream from (VLC → Audio → Audio Device → CABLE Input).
  2. On the listener device, open the listener page and press play. Keep the page in front and the screen on.
  3. Press pause in VLC and count until the listener goes quiet. Repeat 3 times.

More precise: film the PC screen and the listener device together with a second phone, then step through the video frame by frame (30 frames = 1 second). Use the device's speaker or wired earphones; Bluetooth adds its own delay.

Compare, then wait an hour

  • Test a cabled laptop, a Wi-Fi phone and a Wi-Fi laptop at the same time, on the same stream. The cabled one shows what this PC delivers.
  • Leave them playing for an hour and repeat every 15 minutes.
  • If one gets slow: is the cabled laptop still about 1 second? Then reload the page on the slow device. Back to 1 second: that device's Wi-Fi dropped. Still slow: weak Wi-Fi at that spot. Cabled laptop slow too: something on this PC.
  • Change one thing at a time between rounds: router, distance from the access point, 5 GHz vs 2.4 GHz, audio source.

What to send the developer

The version (next to the logo on the dashboard), a short table of time · device · browser · cable or Wi-Fi · router · delay, the audio source you used, and, if this PC has no internet, the file from Admin account → Export diagnostics.

Full guide with a results template: docs/FIELD-TESTING.md in the repository (also linked from the release page on GitHub).

insightsUsage statistics & diagnostics

LANStreamer sends anonymous usage statistics to the developer so field problems can be fixed: app version, OS build, stream format and bitrate, errors, and how far behind live listeners are. Never audio, stream or device names, file paths, or names of people or computers. Turn it off in Admin account → Anonymous usage statistics or from the tray icon.

No internet at the venue

Nothing is lost. The statistics wait in a small file on this PC and are sent, with their original times, the next time LANStreamer runs with internet.

A PC that is never online

Open Admin account and press Export diagnostics. A file named lanstreamer-diagnostics-….json is saved to your Downloads; send it to the developer by WhatsApp or email. The card shows when you last exported, and the app reminds you at start-up when statistics from earlier sessions are still waiting.

Turning statistics off deletes the waiting file.

memoryMinimum specs

  • Windows 10/11 (64-bit), 4 GB RAM, dual-core CPU
  • FFmpeg and Icecast 2.4+ (bundled with the installer)
  • Wired or solid Wi-Fi to the same network as the listeners
  • Listeners: any modern phone browser (Chrome/Safari/Edge, ~2019+)
